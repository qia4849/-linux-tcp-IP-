Linux 入门学习指南

适用环境：Windows + WSL2 + Ubuntu 24.04 LTS

第 0 章　如何进入 Linux

方法一：PowerShell / CMD 输入 wsl（推荐）

  1. 按 Win+R，输入 powershell，回车打开 PowerShell
  2. 输入命令并回车：wsl
  3. 看到类似 administrator@MICROSO-HQNKNJR:~$ 即成功

提示：提示符格式为 用户名@主机名:当前目录$，~ 表示家目录。

方法二：从开始菜单启动

点击开始菜单，搜索 Ubuntu 24.04，点击即可打开。

方法三：指定发行版进入

wsl -d Ubuntu-24.04          # 指定发行版进入
wsl --cd ~                   # 进入后直接定位到家目录

常用操作

exit                          # 退出 Linux（或按 Ctrl + D）
wsl --shutdown                # 完全关闭 WSL（在 PowerShell 中执行）
wsl -l -v                     # 查看发行版列表和状态

TCP/IP 网络协议学习指南

面向初级运维岗位 · 配合《Linux 入门学习指南》对照学习

适用环境：Windows + WSL2 + Ubuntu 24.04 LTS（命令均在 Ubuntu 内验证可执行）

第 0 章　为什么运维必须懂网络

运维日常工作的 80% 都和网络有关：服务器上不了网、端口起不来、域名解析失败、网站 502...... 排查这些问题的前提就是理解 TCP/IP 模型。

  • Linux 学的 ip / ss / ping / curl 这些命令，本质都是操作或观测 TCP/IP 协议栈
  • 本文档每章都给出「Linux 对照命令」，让你边学边练

第 1 章　网络分层模型（面试第一问）

1.1 两种模型对照

层级OSI 七层模型TCP/IP 四层模型典型协议典型设备/工具
7应用层应用层HTTP、DNS、DHCP、SSH、FTP浏览器、curl、nginx
6表示层（并入应用层）SSL/TLS 加密证书
5会话层（并入应用层）会话管理-
4传输层传输层TCP、UDPss、netstat、nc
3网络层网际层IP、ICMP、ARP路由器、ping、ip
2数据链路层网络接口层以太网、MAC 地址交换机、网卡
1物理层网络接口层网线、光纤、信号网线、光模块

记忆口诀：物 数 网 传 会 表 应

核心思想：每一层只负责自己的事，上层调用下层，下层为上层服务（封装与解封装）

1.2 数据封装过程（必须理解）

应用层数据 → 加 TCP 头(端口) → 加 IP 头(源/目的IP) → 加 MAC 头(源/目的MAC) → 发送
# 接收方反向解封装：剥 MAC → 剥 IP → 剥 TCP → 得到应用数据

1.3 运维排查思维：分层定位

故障定位从哪层开始？ 经典顺序（从下往上）：

  1. 链路层：网线/网卡通不通 → ip link
  2. 网络层：网关通不通 → ping 网关IP
  3. 传输层：端口通不通 → ss -tlnp / nc -vz IP 端口
  4. 应用层：服务本身有没有问题 → curl -v 看响应

第 2 章　IP 地址与子网划分

2.1 IPv4 地址基础

  • IPv4 共 32 位（4 个字节），点分十进制表示：192.168.1.100
  • 每个地址 = 网络部分 + 主机部分，分隔符就是子网掩码
  • 子网掩码：255.255.255.0 = 前 24 位是网络位，简写 /24（CIDR 表示法）
192.168.1.100/24
→ 网络部分：192.168.1   （路由只看这部分决定发往哪里）
→ 主机部分：.100       （在网段内区分具体主机）

2.2 私网地址

网段掩码说明
10.0.0.0/8255.0.0.0大型企业内网
172.16.0.0/12255.240.0.0中型网络（Docker 默认 172.17.0.0/16）
192.168.0.0/16255.255.0.0家用路由器最常见（192.168.1.x）

私网地址不能直接上公网，需要 NAT 转换。

特殊地址：127.0.0.1（回环）、0.0.0.0（任意地址/默认路由）、255.255.255.255（广播）

2.3 子网划分核心公式（背下来）

可用主机数 = 2^主机位数 - 2
# 减 2：一个给网络地址（主机位全 0），一个给广播地址（主机位全 1）
CIDR子网掩码网段内地址总数可用主机数
/8255.0.0.016,777,21616,777,214
/16255.255.0.065,53665,534
/24255.255.255.0256254
/25255.255.255.128128126
/26255.255.255.1926462
/27255.255.255.2243230
/30255.255.255.25242（点对点链路正好）

2.4 计算题范例

题目：192.168.1.100/26，求网络地址、广播地址、可用主机范围

/26 → 掩码 255.255.255.192 → 每个子网 64 个地址（256 ÷ 4）

192.168.1.0 ~ 192.168.1.63    ← 第 1 个子网
192.168.1.64 ~ 192.168.1.127  ← 第 2 个子网（100 落在这里！）
192.168.1.128 ~ 192.168.1.191
192.168.1.192 ~ 192.168.1.255

答案：
网络地址：192.168.1.64
广播地址：192.168.1.127
可用主机：192.168.1.65 ~ 192.168.1.126（62 台）

速算技巧：子网块大小 = 256 - 掩码最后一段。如掩码 192 → 块 = 256-192 = 64，然后找 IP 落在哪个 64 的整数倍区间。

2.5 Linux 对照命令

$ ip addr                    # 查看本机 IP 和掩码（/24 这种就是 CIDR）
$ ip route                   # 查看路由：default via 192.168.1.1 就是网关
$ ip route show default
default via 192.168.1.1 dev eth0

2.6 IPv6 简介（了解即可）

128 位，如 2001:db8::1（:: 代表连续 0），地址数量 2^128，彻底解决 IPv4 枯竭。

运维只需知道：ip -6 addr 查看、ping6 测试、::1 是回环。

第 3 章　核心协议详解（TCP 握手是重中之重）

3.1 ARP —— 把 IP 变成 MAC 地址

作用：知道对方 IP，但数据链路层只认 MAC 地址，所以先发广播问「谁的 IP 是 192.168.1.1？报上你的 MAC」。

缓存：查一次记一会（arp -a 可看）

$ ip neigh          # Linux 查看 ARP 缓存
192.168.1.1 dev eth0 lladdr 5c:ea:1d:xx:xx:xx REACHABLE

3.2 ICMP —— 网络层探测协议

作用：报告网络错误和探测连通性，ping 和 traceroute 都靠它。

$ ping -c 4 8.8.8.8     # 发 4 个包，看丢包率和延迟
$ traceroute baidu.com  # 逐跳显示到达目标的路径，定位卡在哪一跳

3.3 TCP —— 可靠传输协议（面试必考）

特点：面向连接、可靠、有序、全双工；有确认、重传、流量控制、拥塞控制。适合：网页、文件传输、数据库等。

三次握手（建立连接）
客户端                          服务端
  |---- SYN(seq=x) ------------>|  ① 客户端：我要连你
  |<--- SYN+ACK(seq=y,ack=x+1)--|  ② 服务端：收到，我也要连你
  |---- ACK(ack=y+1) ---------->|  ③ 客户端：收到，连接建立

为什么是三次而不是两次？ 三次握手让双方都确认对方的收发能力正常，防止「历史失效连接请求」重新占用资源。

四次挥手（断开连接）
客户端                          服务端
  |---- FIN --------------->|  ① 客户端：我发完了，想关闭
  |<--- ACK ---------------|  ② 服务端：收到你的 FIN
  |<--- FIN ---------------|  ③ 服务端：我也发完了，关闭
  |---- ACK --------------->|  ④ 客户端：收到，关闭（进入 TIME_WAIT）

为什么是四次？ 因为 TCP 是全双工，两个方向要各自独立关闭；服务端收到 FIN 后可能还有数据要发，所以 ACK 和 FIN 不能合并。

TIME_WAIT 是什么？ 主动关闭方在发送最后一个 ACK 后要等 2 个 MSL 才完全关闭。作用：① 确保最后一个 ACK 如果丢了能重发；② 让旧连接的数据包在网络中消亡。

TCP 头部关键字段
字段作用
源端口 / 目的端口标识应用（各 16 位）
序列号 seq保证数据有序，每字节一个编号
确认号 ack期望收到的下一个字节编号
标志位SYN、ACK、FIN、RST、PSH、URG
连接状态机（运维要认得出）
LISTEN       服务端在监听（ss -tlnp 看到）
SYN_SENT     客户端发了 SYN 在等回应
ESTABLISHED  连接已建立（正常工作中）
CLOSE_WAIT   被动关闭方等应用层 close（程序不 close 会堆积！）
TIME_WAIT    主动关闭方等待 2MSL（量大说明短连接多，正常但可调优）
$ ss -tlnp                # 看监听端口（LISTEN）
$ ss -tan | head          # 看所有 TCP 连接状态，排查 ESTABLISHED/CLOSE_WAIT 堆积
$ ss -s                   # 协议统计：看 TIME_WAIT 等数量

第 6 章　常见问题

  1. TCP 三次握手过程？ SYN → SYN+ACK → ACK，目的：双方确认收发能力，防止历史连接干扰。
  2. 为什么挥手要四次？ 全双工，两个方向独立关闭，ACK 与 FIN 无法合并。
  3. TIME_WAIT 是什么？为什么有它？ 主动关闭方等待 2MSL，保证最后一个 ACK 可靠、旧包消亡。
  4. 192.168.1.100/24 有多少可用主机？ 254（256-2）。
  5. /26 子网多大？ 64 个地址，62 台可用主机。
  6. 502 和 504 区别？ 502=网关收到后端无效响应；504=网关等后端超时。
  7. DNS 用的什么协议和端口？ UDP 53（TCP 53 用于大响应/区域传输）。
  8. 私网地址有哪些段？ 10/8、172.16/12、192.168/16。
  9. 端口分几类？ 0-1023 知名端口、1024-49151 注册端口、49152-65535 动态端口。
  10. 公司服务器连不上外网，怎么排查？ ping 网关 → ping 公网 IP → 查 DNS → 查防火墙/路由 → 查代理。
  11. HTTP 403 和 404 区别？ 403=有资源但没权限；404=资源不存在。
  12. 如何确认服务器某个端口是否被占用？ ss -tlnp / lsof -i:端口。
  13. HTTP 和 HTTPS 区别？ HTTPS 有 TLS 加密、默认 443 端口、需证书。
  14. 什么是 NAT？ 内网私网 IP 转换成公网 IP 的技术，家用路由器都在用。
  15. traceroute 原理？ 利用 IP 包 TTL 逐跳递减，每跳超时返回 ICMP 报错，从而画出路径。
